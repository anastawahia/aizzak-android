## 3. الطباعة

يستخدم التطبيق خط النظام الداعم للإنجليزية والعربية، بلا خط شبكي أو تنزيل. القيم أدناه مستقلة عن `MaterialTheme` الافتراضي ويجب تعريفها صراحةً:

| الرمز | الحجم/الارتفاع | الوزن | الاستخدام |
|---|---|---|---|
| `screenTitle` | `28sp / 34sp`، و`30sp / 36sp` في expanded | 650 | عنوان الشاشة `h1` |
| `sectionTitle` | `20sp / 28sp` | 650 | هوية الحساب وعنوان قسم كبير |
| `cardTitle` | `16sp / 22sp` | 650 | اسم الوكيل أو عنوان صف رئيسي |
| `body` | `16sp / 24sp` | 400 | النص الأساسي والقيم |
| `supporting` | `14sp / 23sp` | 400 | المقدمة والوصف وتفاصيل الصف |
| `label` | `14sp / 20sp` | 600 | تسمية الحقل والزر |
| `sectionLabel` | `11sp / 16sp` | 600 | عنوان panel بحروف متباعدة حيث تسمح اللغة |
| `eyebrow` | `11sp / 16sp` | 650 | مقدمة Home العليا؛ لا يفرض uppercase على العربية |
| `navigationLabel` | `11sp / 16sp` | 500/650 | تسمية الوجهة؛ 650 للنشطة |
| `statusChip` | `10sp / 15sp` | 600 | حالة الوكيل |

## 4. المسافات، المقاسات والأشكال

- سلم المسافات: `4, 8, 12, 16, 20, 24, 28, 32dp`؛ لا تُنشأ قيم اعتباطية لكل شاشة.
- شريط AIZZAK: padding أفقي `22dp`، علوي `17dp`، سفلي `15dp`، gap `9dp`، الشعار الأصلي `36×36dp`.
- محتوى compact: padding أفقي `22dp`، علوي `17dp`، سفلي `28dp`. محتوى expanded: أفقي `34dp` وعلوي `28dp`.
- عرض المحتوى العام الأقصى `1080dp` (المرجع `1060px` داخل الإطار)، وعرض النماذج/الحساب/الإعدادات الأقصى `440dp`.
- الأزرار والحقول: نصف قطر `12dp`، حد أدنى مرئي `50dp`، ومساحة لمس لا تقل عن `48×48dp`.
- بطاقات الوكلاء: نصف قطر `20dp`، padding `20dp`، gap `15dp` في compact، وحد `1dp` من `outlineVariant` مع حافة start بلون الوكيل.
- حاوية أيقونة الوكيل: `42×42dp`، نصف قطر `13dp`، والأيقونة `24dp`.
- panels المتصلة: نصف قطر `17dp`، حد `1dp`، overflow مقصوص بالشكل؛ الصف `62dp` على الأقل وpadding `16dp`.
- تنبيه/Callout: نصف قطر `12dp`، padding `13dp × 14dp`، gap `10dp`، أيقونة `19dp`.
- صورة الحساب: `70×70dp` دائرية. أيقونة الحالة الكبيرة: `62×62dp`، نصف قطر `18dp`، أيقونة `28dp`.
- شريحة الحالة: شكل pill كامل، padding `5dp × 9dp`، ونقطة حالة `5dp`.
- لا gradients ولا elevation ثقيل. الفصل يأتي من السطح والحدود والمسافات.

## 5. عقد المكونات المشتركة

| المكون | البنية الملزمة | الحالات المرئية |
|---|---|---|
| `AizzakAppBar` | الشعار الأصلي ثم AIZZAK والوصف في عمود؛ start-aligned في اللغتين | ثابت في الشاشات العشر، لا يتحول إلى شعار 64dp داخل المحتوى |
| `AdaptiveMainNavigation` | Home وAccount وSettings بأيقونة وتسمية؛ bottom bar دون 600dp وrail من 600dp | النشطة: pill ممتلئ `primary/onPrimary` وتسمية أثقل و`selected` semantics؛ لا لون منفرد |
| `ScreenHeading` | eyebrow اختياري، عنوان heading، مقدمة supporting | ترتيب start ثابت ومسافات المرجع، لا يُدمج مع Brand |
| `LabeledField` | label خارج الحقل، field surface/outline، نص مساعدة/خطأ تحته، reveal داخل end عند كلمة المرور | focused: إطار وحلقة `focusRing`؛ error: رسالة وأيقونة/دلالة لا لون فقط؛ disabled: `surfaceVariant` مع منع التفاعل؛ busy لا يمسح القيمة |
| `PrimaryAction` | زر ممتلئ بعرض النموذج | pressed state layer قصير؛ focused ring 3dp؛ disabled دلالة بصرية ونص محفوظ؛ loading يمنع التكرار ويُبقي تسمية مفهومة |
| `SecondaryAction` | outlined بعرض النموذج؛ text للأفعال الأقل تأكيداً | نفس focus/touch target؛ لا ينافس الإجراء الرئيسي بصرياً |
| `DangerAction` | `errorContainer/onErrorContainer` مع تسمية Sign out | لا يُعبّر عن الخطر باللون فقط؛ busy على الزر نفسه؛ الخروج محلي وفق العقد |
| `ConnectedPanel` | surface بحد وشكل واحد، صفوف تفصلها `outlineVariant` | الصف القابل للاختيار يملك كامل مساحة اللمس؛ radio في end؛ الفصل لا يصبح بطاقات مستقلة |
| `InformationNotice` | أيقونة info + نص داخل `primaryContainer` | role/status عند تغيّر الرسالة؛ لا تكرار إعلان الأيقونة |
| `ErrorNotice` | أيقونة تحذير + عنوان/نص وإجراء عند الحاجة | رسالة آمنة لا تعرض raw error؛ تعلن مرة واحدة عند التغيير |
| `AssistantCard` | حافة start، حاوية أيقونة، اسم LTR، وصف، status chip | non-clickable دائماً في هذا النطاق، لا ripple/chevron/role button |
| `BackAction` | سهم اتجاهي + تسمية مترجمة | السهم فقط ينعكس في RTL؛ touch target 48dp؛ يظهر في الشاشات المحددة فقط |
| `CenteredState` | أيقونة أو loader ثم عنوان ومقدمة وإجراءات | لا ارتفاع ثابت يحجب المحتوى؛ قابل للتمرير عند ارتفاع مضغوط |

الأيقونات خطية بسُمك قريب من `1.65dp`، والنشطة/القابلة للنقر لها وصف مترجم. أيقونات الوكلاء والتنبيه المصاحب لنص مكافئ زخرفية ولا تعاد تسميتها لقارئ الشاشة.

## 6. التكيف، RTL والوصول

- `<600dp`: bottom navigation وعمود Home واحد. `600–839dp`: rail وعمودان فقط إذا بقي النص مقروءاً. `≥840dp`: rail وحتى ثلاثة أعمدة، مع الهبوط عند font scale أو ضيق الارتفاع.
- تستخدم كل المسافات `start/end`. يبقى البريد وكلمات المرور وأسماء الوكلاء LTR داخل واجهة RTL. لا تنعكس إلا الأسهم والرموز الاتجاهية.
- الحقول تمريرية مع IME insets؛ لا autofocus. `Next` ينتقل للحقل التالي و`Done` ينفذ الإجراء الصالح مرة واحدة.
- ترتيب التركيز يتبع ترتيب المخزون: الشريط غير التفاعلي، العنوان/المقدمة، الحقول، الإجراء الرئيسي، الإجراءات الثانوية، ثم التنقل عند وجوده. بعد validation ينتقل التركيز لأول حقل غير صالح ويعلن ملخص واحد.
- يحترم التطبيق تقليل الحركة. لا shimmer أو حركة مستمرة لبطاقات الوكلاء؛ loader وحده متحرك ولا يكرر إعلاناً صوتياً.
- أهداف التباين `4.5:1` للنص و`3:1` للنص الكبير والمؤشرات. هذه أهداف تحقق لاحقة وليست شهادة امتثال.

## 7. تكوينات اللقطات

تُلزم `screen-inventory.json` كل شاشة بأربع لقطات ثابتة على الأقل: English/light/compact، Arabic/dark/compact، English/dark/expanded، وArabic/light/expanded عند font scale `1.5`. تعرض fixtures بيانات placeholder غير شخصية وتثبت الوقت/الحركة/الحالة. اسم الملف يتبع `<SCR-ID>__<locale>_<theme>_w<width>_fs<scale>.png`.
