# رموز تصميم شاشات Data Search

الحالة: مرشح اعتماد محدث لمرحلة `design`  
التاريخ: 2026-11-06  
النطاق: `SCR-DS-001..010`، مرتبط بـ`DS-REQ-01..13`

## 1. المبدأ

يحافظ التصميم على نظام AIZZAK الحالي في `AizzakTheme.kt` ولا ينشئ هوية موازية. الأزرق يبقى لون الإجراء العام، والسماوي (`secondary`) يميز Data Search داخل الأيقونة والحواف وحالات المصادر. كل حالة تحمل نصاً وأيقونة أو شكلاً؛ اللون وحده لا يحدد المعنى.

لا تُفعل Dynamic Color في هذا المرجع، لأن المنتج الحالي يثبت لوحة AIZZAK. أي قرار لاحق بتفعيلها يحتاج مراجعة التباين والمرجع البصري من جديد.

## 3. الطباعة

تستعمل خط النظام الداعم للعربية والإنجليزية، وفق Typography الحالي:

| الاستخدام | رمز Compose المستهدف | القيمة المرجعية |
|---|---|---|
| عنوان الشاشة | `headlineLarge` | 28sp / 34sp / Bold |
| عنوان حالة أو تفصيل | `headlineMedium` | 24sp / 30sp / Bold |
| عنوان قسم | `titleLarge` | 20sp / 26sp / SemiBold |
| عنوان بطاقة/مصدر | `titleMedium` | 16sp / 22sp / SemiBold |
| متن | `bodyLarge` | 16sp / 24sp |
| وصف وبيانات وصفية | `bodyMedium` | 14sp / 21sp |
| زر أو حالة | `labelLarge` | 14sp / 20sp / SemiBold |

يتمدد ارتفاع العناصر مع `fontScale` ولا يثبت عدد الأسطر للعناوين. أسماء الملفات والمعرفات تعرض باتجاه المحتوى المناسب داخل RTL دون عكس الأحرف.

## 4. المسافات والأشكال

- شبكة المسافات: 4، 8، 12، 16، 20، 24، 32dp.
- هامش compact: 20dp؛ expanded: 30–32dp مع محتوى أقصى 980dp.
- `extraSmall = 8dp`: عناصر صغيرة فقط.
- `small = 12dp`: حقول، أزرار، وتنبيهات.
- `medium = 20dp`: بطاقات وحوار.
- الحبة الدائرية: حالة المصدر والمرشحات.
- الحد 1dp؛ لا ظلال ثقيلة أو gradients.
- جميع الأهداف التفاعلية 48×48dp على الأقل. صف المصدر أو النتيجة كله هدف واحد، وإجراء مستقل لا يدمج دلالياً داخله.

## 5. المكونات وحالاتها

### سياق المساحة

- شريحة سماوية أسفل عنوان Data Search تعرض اسم المساحة المحددة في كل شاشة مرتبطة بالبيانات.
- اختيار المساحة شاشة مستقلة تعرض مساحات موجودة فقط، مع عدد الملفات والاستخدام المتاحين من العقد.
- لا يُعرض إنشاء أو تعديل أو حذف مساحة؛ حالة عدم وجود مساحة مانعة وواضحة.
- تبديل المساحة يفرغ بيانات المساحة السابقة قبل الجلب، ولا يستعمل اللون أو الذاكرة المحلية كتفويض.

### مرحلتا الملف والفهرسة

- كل مصدر يعرض سطرين مستقلين دائماً: **سلامة الملف** و**فهرس البحث**.
- سلامة الملف: `uploaded` محايد، `scanning` عنبري، `ready` سماوي، و`quarantined` خطأ.
- فهرس البحث: «لم تبدأ» محايد، `pending/indexing` عنبري، `indexed` سماوي، و`failed` خطأ.
- لا يعني `ready` أن المصدر قابل للبحث؛ لا تظهر قابلية البحث إلا مع `indexed`.
- تستخدم رحلة الإضافة قائمة مراحل عمودية قابلة للتمدد بدلاً من نسبة تقدم غير متوفرة في العقد.

### لقطة العقد

- شارة المراجعة العنبرية خارج نموذج المنتج توضّح أن المرجع مبني على
  `chore/public-file-links-closing@ff547ad…` وليس `master` مؤكداً.
- هذه الشارة لا تنتقل إلى شاشة المنتج النهائية؛ غرضها منع اعتماد التصميم كدليل تكامل.

### شريط Data Search

- رجوع باتجاهي ينعكس في RTL.
- eyebrow ثابت `DATA SEARCH` يبقى LTR بوصفه الاسم الرسمي.
- الإجراء النصي في الطرف المقابل مثل «المصادر» أو «إضافة مصدر».
- في expanded يبقى rail العام، ويظهر Data Search كوجهة محددة بالنص والأيقونة والخلفية.

### حقل البحث

- Label ظاهر دائماً، وليس placeholder وحده.
- ارتفاع أدنى 50dp في المرجع و56dp عند Compose إذا أعاد استخدام `OutlinedTextField`.
- الإجراء الأساسي منفصل ويصبح بعرض كامل عندما لا يتسع الصف أو يكبر الخط.
- مع عدم وجود مصدر جاهز أو offline: تعطيل مع شرح نصي قريب، لا تعطيل صامت.

### المصدر

- اسم، نوع مؤكد فقط، آخر تحديث مؤكد فقط، وحالة نصية.
- `ready/indexed`: نقطتان وسطران منفصلان، كلاهما سماوي مع النص الكامل.
- `scanning` أو `pending/indexing`: نقطة عنبرية بلا نسبة غير مؤكدة.
- `quarantined` أو `failed`: نقطة وحاوية خطأ، مع بقاء المرحلتين منفصلتين.
- لا تعرض صيغة أو حجم أو حالة progress قبل تثبيت العقد.

### النتيجة

- مقتطف + اسم مصدر + الصفحة والقسم عندما لا يكونان `null`.
- صف كامل قابل للفتح، ولا يدعي أنه إجابة مولدة.
- إبراز المطابقة: حاوية العنبر مع خط سفلي، كي لا يعتمد على اللون وحده.
- عند الخطأ الجزئي تبقى النتائج المؤكدة ويظهر تنبيه قبل القائمة.
- النتائج Top-k (الافتراضي 5) ولا تعرض score أو cursor أو إجابة مولدة.

### تحذير الاستبدال

- حوار هدّام يظهر قبل التسجيل عندما يكتشف العميل اسماً مطابقاً داخل المساحة.
- يذكر أن الإكمال قد يستبدل الملف الحي الأقدم ويطهر فهرسه، وأن الفحص best-effort ولا يمنع سباقاً متزامناً.
- التركيز الأول على الإلغاء، ولا يبدأ الرفع قبل التأكيد.

### الإجراءات

- Primary: بحث أو إضافة المصدر عندما يكون صالحاً.
- Secondary/outlined: فتح مصدر أو إلغاء عادي.
- Text: عرض الكل أو إجراء منخفض الأهمية.
- Danger: حذف المصدر داخل حاوية error.
- Disabled: surfaceVariant + onSurfaceVariant مع منع التفاعل وشرح السبب.
- Pressed: تغذية راجعة قصيرة بخفض الإضاءة؛ Focus: حلقة primary بعرض 3dp. تقليل الحركة يلغي الانتقالات غير الضرورية.

### حوار الحذف

- Dialog بحاوية surface وشكل 20dp.
- العنوان يذكر اسم الملف، والنص يصرح بالحذف الناعم للملف والتطهير غير القابل للتراجع للمستندات والقطع والفهرس وفق لقطة العقد.
- التركيز الأول على الإلغاء؛ الإلغاء قبل الحذف في ترتيب القراءة، والحذف لا يزيل العنصر قبل تأكيد الخدمة.

## 6. التكيف

| المساحة | السلوك |
|---|---|
| `<600dp` | شاشة واحدة، هوامش 20dp، الأفعال تلتف أو تتحول لعمود، وBack يعيد بالتسلسل المحدد. |
| `600–839dp` | rail عام؛ يمكن لوحتان إذا سمح الارتفاع والخط. |
| `>=840dp` | قائمة/نتائج في لوحة ابتدائية، وتفاصيل أو إرشاد اختيار في لوحة نهائية. أقصى محتوى 980dp. |
| `fontScale >=1.3` أو ارتفاع ضيق | يجوز الانهيار إلى لوحة واحدة؛ لا نص مقطوع ولا أزرار ثابتة الارتفاع. |

## 7. الوصول والتدويل

- ترتيب القراءة: الشريط، عنوان الشاشة، التنبيه، الإجراء الرئيسي، المحتوى، الإجراءات الثانوية.
- العناوين Headings، وحالة التحميل `progressbar` أو إعلان مقتصد عند التغير المهم.
- الأيقونات الزخرفية بلا وصف؛ الأزرار الأيقونية لها تسمية مترجمة.
- RTL يعكس start/end والرجوع فقط؛ اسم Data Search وأسماء الملفات قد تبقى LTR وفق المحتوى.
- الخطأ يتضمن عنواناً ونصاً وإجراء، وليس إطاراً أحمر فقط.
- المرجع يغطي en/ar، light/dark، compact/expanded، ومقياس 1.3. لا يمثل ذلك دليلاً على TalkBack أو جهاز فعلي.

## 8. قيود واجبة قبل التنفيذ

التصميم يثبت بصرياً الحاجة إلى `space_id` ومسار الرفع والفهرسة ونتائج المقتطفات كما تصفها لقطة API. لكنه لا يثبت أن اللقطة منشورة على `master`، ولا يثبت مفتاح Data Search، مصدر الصلاحيات، أسماء صلاحيات الملفات الدقيقة، MIME/الصيغ/الأحجام، قبول `text/plain`، استعادة رابط رفع منتهٍ، cache/offline، أو حفظ المسودة. يجب تأكيد هذه النقاط من مالك الباك إند قبل بناء السلوك المتأثر.
