# مخططات Data Search Agent — عقد الملفات والمعرفة

الحالة: Low fidelity — البنية والترتيب فقط  
المرجع: `ux-journeys.md`  
الشاشات: `SCR-DS-001..010`

> تنبيه عقدي: المخططات مبنية على لقطة `chore/public-file-links-closing@ff547ad…` وليست عقد `master` المؤكد. لا تصبح أساس تنفيذ قبل تأكيد الباك إند.

## قواعد مشتركة

- يظهر اسم المساحة المحددة في كل شاشة داخل الوكيل، وتغييرها يفرغ محتوى المساحة السابقة.
- `[زر]` تفاعلي، `(حالة)` نص، `{قائمة}` قابلة للتمرير. ترتيب الرسم هو ترتيب القراءة.
- سطر **سلامة الملف** (`FileOut`) مستقل دائماً عن سطر **حالة الفهرسة** (`DocumentOut`).
- في expanded: القوائم والنتائج في pane ابتدائي والتفاصيل في pane نهائي؛ عند font scale≥1.3 يجوز الانهيار لشاشة واحدة.
- كل loading/error/offline/denied/session state يبقي عنوان الشاشة وسياق المساحة، ثم يعرض المخرج قبل أي بيانات.

## SCR-DS-009 — اختيار مساحة موجودة / لا توجد مساحة

**يخدم:** DS-REQ-02، 03، 09، 13  
**الدخول:** بعد تفعيل Data Search أو من شريحة المساحة.  
**الخروج:** اختيار إلى SCR-DS-001؛ Back للرئيسة.

```text
┌────────────────────────────────────┐
│ [رجوع]  اختر مساحة                │
├────────────────────────────────────┤
│ أين توجد بياناتك؟                 │ heading
│ اختر مساحة موجودة للملفات والبحث. │
│                                    │
│ { [اسم المساحة                    ]│
│    عدد الملفات · المساحة المستخدمة│
│   [اسم مساحة أخرى                 ]│
│   [تحميل المزيد — cursor]          │
│ }                                  │
└────────────────────────────────────┘
```

- **No space:** «لا توجد مساحة متاحة» + `[تحديث]` + `[العودة للرئيسة]`. لا زر إنشاء أو إدارة.
- **Loading/error/offline:** القائمة لا تستعمل cache كإذن؛ offline يعرض آخر اختيار فقط إذا أمكن تأكيده دون كشف بيانات، وإلا يمنع الدخول.
- **Permission/session:** لا أسماء مساحات؛ رجوع/دخول.
- مساحة وحيدة يمكن تحديدها مع بقاء اسمها مرئياً. pagination cursor حتى `next_cursor=null`.

## SCR-DS-001 — لوحة Data Search لمساحة واحدة

**يخدم:** DS-REQ-01..03، 07..10، 13

```text
┌────────────────────────────────────┐
│ [رجوع] Data Search      [المصادر] │
│ المساحة: [اسم المساحة ▾]           │
├────────────────────────────────────┤
│ ابحث في محتوى هذه المساحة          │ heading
│ تسمية: استعلام البحث               │
│ [                                 ]│
│ [بحث]                              │
│ (يبحث في المصادر indexed فقط)      │
│                                    │
│ [إضافة مصدر]                       │
│   [إضافة نص] [اختيار ملف]          │
│                                    │
│ حالة المصادر                       │ heading
│ (جاهزة للبحث / قيد الفحص / فهرسة)  │
│ {آخر المصادر: اسم + سلامة + فهرسة} │
│ [عرض المكتبة]                      │
└────────────────────────────────────┘
```

- **Empty:** لا ملفات + إجراءات الإضافة المسموحة؛ البحث معطل بسبب واضح.
- **No indexed documents:** الملفات موجودة لكن البحث معطل: «لا توجد مصادر مفهرسة».
- **Read only:** البحث/المكتبة متاحان مع `knowledge:read`; الإضافة/index معطلان بحسب الصلاحيات.
- **Denied/session:** تحجب الأسماء والمقتطفات، لا cache.
- **Offline:** لا upload/index/search جديد؛ البيانات المخزنة محجوبة افتراضياً حتى سياسة معتمدة.

## SCR-DS-002 — إضافة نص كملف UTF-8

**يخدم:** DS-REQ-03..06، 09، 10، 12، 13

```text
┌────────────────────────────────────┐
│ [رجوع]  إضافة نص                  │
│ المساحة: اسم المساحة               │
├────────────────────────────────────┤
│ أضف نصاً كمصدر                     │ heading
│ سيُحوّل إلى UTF-8 text/plain ثم    │
│ يمر بالفحص والفهرسة مثل أي ملف.     │
│                                    │
│ تسمية: اسم المصدر/الملف            │
│ [                                 ]│
│ تسمية: المحتوى                     │
│ [                                 ]│
│ [                                 ]│
│ (لا حد رقمي حتى تأكيد master)      │
│                                    │
│ [إضافة وفهرسة] [إلغاء]             │
└────────────────────────────────────┘
```

- submit ينشئ bytes UTF-8 ثم ينتقل لمسار upload نفسه؛ لا endpoint نص.
- الاسم المطابق يفتح SCR-DS-010 قبل التسجيل.
- **Submitting:** مراحل معلنة: تجهيز محلي ← تسجيل ← رفع ← complete ← scanning ← ready ← طلب index ← pending/indexing.
- فشل مرحلة لا يحول الأخرى إلى فشل. موت العملية يصالح IDs/keys.
- Back مع مسودة يفتح تأكيد تجاهل؛ حفظها المحلي قرار أمني مفتوح.

## SCR-DS-010 — تحذير استبدال ملف بالاسم نفسه

**يخدم:** DS-REQ-12، 13  
**الدخول:** بعد فحص كل صفحات files ووجود اسم حي مطابق lower(NFC)، وقبل التسجيل/الرفع.

```text
┌────────────────────────────────────┐
│ استبدال «اسم الملف»؟              │ heading
│ يوجد ملف حي بالاسم نفسه في هذه     │
│ المساحة. عند اكتمال الرفع قد يُحذف  │
│ الملف الأقدم ويُطهّر فهرسه بلا تراجع.│
│ قد يحدث تصادم متزامن بعد هذا الفحص.│
│                                    │
│ [إلغاء]      [متابعة والاستبدال]   │
└────────────────────────────────────┘
```

- focus على إلغاء. لا يبدأ التسجيل قبل التأكيد.
- هذا تحذير best-effort؛ لا يَعِد بمنع السباق ولا يحدد أي ملف نهائياً دون عقد ذري.

## SCR-DS-003 — مكتبة المصادر الموحدة

**يخدم:** DS-REQ-03، 05، 07، 09، 11، 13

```text
┌────────────────────────────────────┐
│ [رجوع] المصادر        [إضافة مصدر]│
│ المساحة: [اسم المساحة ▾]           │
├────────────────────────────────────┤
│ مصادر المساحة                      │ heading
│ {                                  │
│  [اسم الملف                        ]│
│   السلامة: ready/scanning/...       │
│   الفهرسة: indexed/pending/...      │
│  --------------------------------  │
│  [الملف التالي ...                 ]│
│ }                                  │
│ (حالة صفحات files) [تحميل المزيد]  │
│ (حالة صفحات documents)[تحميل المزيد]│
└────────────────────────────────────┘
```

- دمج حصراً: `DocumentOut.file_id == FileOut.id`.
- cursor مستقل للقائمتين؛ لا عبارة «كل المصادر» حتى `next_cursor=null` في كليهما.
- مستند وصل قبل صف ملفه: placeholder غير كاشف بـfile_id مختصر فقط إن كان آمناً، أو «جارٍ جلب الملف».
- ملف بلا مستند: «غير مفهرس»، لا «فشل».
- quarantined: «محجور / غير قابل للفهرسة»؛ failed: «جاهز / فشلت الفهرسة».
- نقص file read يحجب القائمة؛ نقص knowledge read يحجب حالة المستند/البحث ولا يستنتجها.

## SCR-DS-004 — تفاصيل المصدر وحالتاه

**يخدم:** DS-REQ-04، 05، 07، 09، 11، 13

```text
┌────────────────────────────────────┐
│ [رجوع] تفاصيل المصدر              │
│ المساحة: اسم المساحة               │
├────────────────────────────────────┤
│ اسم الملف                          │ heading
│ MIME · الحجم (من FileOut)          │
│                                    │
│ سلامة الملف                        │ heading
│ uploaded | scanning | ready |       │
│ quarantined                        │
│                                    │
│ حالة الفهرسة                       │ heading
│ لم تبدأ | pending | indexing |      │
│ indexed | failed                   │
│ (لا raw error في DocumentOut)      │
│                                    │
│ [بدء الفهرسة — ready + manage]     │
│ [البحث في المساحة — indexed]       │
│ [حذف الملف وفهرسه]                 │
└────────────────────────────────────┘
```

- `download_url` لا يصبح إجراءً تلقائياً في هذا النطاق.
- إذا كانت نتيجة complete مجهولة: «جارٍ التحقق من سلامة الملف»، لا إعادة رفع.
- `ready` لا يعني indexed؛ `indexed` لا يُعرض دون DocumentOut.
- حذف ينتقل SCR-DS-008، فقط بصلاحية الحذف الفعلية.

## SCR-DS-005 — تنفيذ بحث top-k

**يخدم:** DS-REQ-03، 08..10، 13

```text
┌────────────────────────────────────┐
│ [رجوع] البحث في Data Search       │
│ المساحة: [اسم المساحة ▾]           │
├────────────────────────────────────┤
│ تسمية: استعلام البحث               │
│ [                                 ]│
│ (عدد النتائج: الافتراضي 5)         │
│ [بحث]                              │
│ (جارٍ البحث في هذه المساحة...)     │
└────────────────────────────────────┘
```

- لا مصدر indexed: منع + `[عرض المصادر]`.
- لا cursor ولا infinite scroll. k أكبر حتى 50 لا يظهر إلا بقرار منتج.
- query لا ينفذ دون `space_id` و`knowledge:read`.
- موت العملية يعيد query ولا يعيد POST حتى يقرر المستخدم، لأن البحث قراءة ويمكن تكراره لكن لا يدعي نتيجة قديمة.

## SCR-DS-006 — نتائج top-k

**يخدم:** DS-REQ-08، 09، 13

```text
┌────────────────────────────────────┐
│ [رجوع] نتائج البحث                │
│ المساحة: اسم المساحة               │
├────────────────────────────────────┤
│ [الاستعلام الحالي          ][بحث] │
│ (أفضل 5 نتائج)                     │
│ {                                  │
│  [نص المقتطف                      ]│
│   المصدر: file_name أو «مصدر»      │
│   الصفحة: N · القسم: X (إن وجدا)   │
│  --------------------------------  │
│  [المقتطف التالي                  ]│
│ }                                  │
└────────────────────────────────────┘
```

- لا score افتراضياً، لا جواب مولد، لا cursor.
- null file_name/page/section لا يستبدل ببيانات مختلقة.
- **Empty:** تعديل query. **Denied/session:** حجب النتائج. **Offline:** لا بحث؛ لا نتائج cached افتراضياً.
- «إظهار المزيد» إن اعتمد = طلب جديد بـk أكبر، لا صفحة تالية.

## SCR-DS-008 — تأكيد حذف الملف وفهرسه

**يخدم:** DS-REQ-09، 11، 13

```text
┌────────────────────────────────────┐
│ حذف «اسم الملف» بلا تراجع؟        │ heading
│ سيُحذف الملف من القراءة حذفاً ناعماً│
│ وتُطهّر مستنداته وقطعه وفهرسه.      │
│ لن يظهر في نتائج البحث بعد النجاح. │
│                                    │
│ [إلغاء]       [حذف الملف وفهرسه]   │
└────────────────────────────────────┘
```

- focus على إلغاء، وتأكيد صريح. لا عبارة قابلة للتراجع.
- الصف يبقى «جارٍ الحذف» حتى 204؛ النتيجة المجهولة تُصالح قبل retry.
- حذف غير مصرح لا يظهر ولا يسرّب وجود المورد.

## حالات رحلة الرفع والفهرسة داخل 002/004

```text
[محلي] تجهيز bytes
   ↓
[ملف] POST /files + Idempotency-Key
   ↓
[نقل] PUT upload_url
   ↓
[ملف] POST /files/{id}/complete
   ↓
[سلامة] uploaded → scanning → ready | quarantined
                                  ↓ ready فقط
[معرفة] POST /knowledge/documents + Idempotency-Key → 202
   ↓
[فهرسة] pending → indexing → indexed | failed
```

لا يدمج المرجع البصري المرحلتين في progress واحد يوحي أن upload الآمن يعني searchable.

## توجيه screen inventory والمرجع البصري

- حافظ على `SCR-DS-001..010` ومعرفات العناصر المستقرة.
- حالات مرجعية إلزامية: no-space، اختيار مساحة متعددة الصفحات، لوحة empty، upload/scanning، quarantined، ready-not-indexed، pending/indexing، failed، indexed، مكتبة مدمجة، نتائج فيها/لا تحتوي page/section، replace warning، delete confirmation، denied، session، offline.
- تكوينات اللقطات: EN/LTR وAR/RTL، light/dark، compact phone، expanded، وfont scale 1.3 على الأقل.
- inventory يجب أن يفصل عنصري سلامة الملف وحالة الفهرسة، ويذكر شريحة المساحة في كل شاشة.
- لا يثبت MIME/limits/key الوكيل/صلاحيات الملفات الدقيقة أو أي سلوك غير مؤكد على `master`.
