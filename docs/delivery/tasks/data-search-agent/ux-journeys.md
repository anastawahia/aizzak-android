# رحلات وتجربة Data Search Agent — وكيل RAG محادثي

الحالة: تسليم UX مصحح لمرحلة `design` — قابل للمراجعة وغير معتمد للتنفيذ
التاريخ: 2026-11-06  
المهمة: `data-search-agent`

## 1. التصحيح الحاكم ومصدر الاستدلال

Data Search هو **وكيل محادثة RAG**. واجهته الأساسية سجل محادثة ومؤلف رسالة، وليست نموذج بحث يعيد قائمة مقتطفات. يطرح المستخدم سؤالاً، يسترجع الوكيل من معرفة المساحة، ثم يعرض جواباً مولداً داخل المحادثة مع حالة انتظار/بث/اكتمال واضحة.

استُنبط مبدأ العمل من تطبيق الويب للقراءة فقط، ولا سيما:

- `src/features/rag/pages/SpacesHome.jsx`: المساحة تملك ملفاتها ومحادثاتها.
- `src/features/rag/pages/SpaceView.jsx`: فتح المساحة يوجّه إلى أحدث محادثة، أو ينشئ محادثة أولى إذا كانت المساحة فارغة.
- `src/features/rag/pages/RagConversation.jsx`: السجل، الإرسال، الرد التدريجي، المصالحة مع السجل، وحذف الرسالة.
- `src/features/rag/components/ConversationsPanel.jsx`: إنشاء المحادثات وإعادة تسميتها وحذفها.
- `src/features/rag/components/WorkspaceFiles.jsx`: الملفات مصادر معرفة، والفهرسة وإدارة النطاق وظائف مساندة للمحادثة.

تطبيق الويب **مرجع سلوك منتج، لا إثبات لعقد `master` العامل**. لا تعتمد Android أسماء المسارات أو الحقول أو حالات البث أو الصلاحيات حتى يؤكدها مالك الباك إند كتابةً. لا يعدّل هذا التصميم الباك إند أو تطبيق الويب.

يبقى `docs/product/V1-AGREED-SCOPE.md` حاكماً: لا إنشاء/إعادة تسمية/حذف للمساحات في هذا النطاق. يختار Android مساحة موجودة فقط. أما المحادثات والمصادر داخل المساحة فهي موضوع هذا التصميم اللاحق، ولا تُفعّل بطاقة Data Search قبل إثبات إتاحة الوكيل والعقد.

## 2. نموذج المنتج

```text
Data Search
└── مساحة موجودة
    ├── محادثات المساحة
    │   └── محادثة RAG نشطة
    │       ├── سجل الرسائل
    │       ├── سؤال المستخدم
    │       ├── جواب مولد/متدفق
    │       ├── نموذج المحادثة، إذا أكده العقد
    │       └── نطاق الاسترجاع
    │           ├── بلا تثبيت: كل المصادر المفهرسة في المساحة
    │           └── مع تثبيت: الملفات المثبتة فقط
    └── مصادر معرفة المساحة
        ├── رفع ملف أو إضافة نص كملف
        ├── سلامة الملف
        ├── حالة الفهرسة
        └── إعادة تسمية/حذف/تلخيص إذا أكدها العقد
```

لا توجد رحلة «بحث ← نتائج top-k ← مقتطف منفصل» في الواجهة الأساسية. الاسترجاع عملية داخلية تخدم الجواب. إن أعاد العقد مراجع مصادر منظمة، تظهر مع رسالة المساعد؛ وإن لم يعدها فلا تخترع الواجهة استشهادات أو أرقام صفحات.

## 4. بنية المعلومات والشاشات

```text
الرئيسة
└── Data Search (بعد تحقق الإتاحة)
    ├── SCR-DS-001 اختيار مساحة موجودة / لا توجد مساحة
    └── SCR-DS-002 محادثة RAG للمساحة
        ├── SCR-DS-003 قائمة محادثات المساحة
        ├── SCR-DS-004 إنشاء/إعادة تسمية محادثة
        ├── SCR-DS-005 تأكيد حذف محادثة
        ├── SCR-DS-006 مصادر معرفة المساحة
        ├── SCR-DS-007 إضافة مصدر ومتابعة تجهيزه
        ├── SCR-DS-008 تفاصيل المصدر وحالته
        ├── SCR-DS-009 نطاق استرجاع المحادثة
        └── SCR-DS-010 تأكيد حذف مصدر
```

`SCR-DS-002` هي وجهة العمل الرئيسة. القوائم والمصادر والنطاق أدوات تفتح منها ثم تعود إليها؛ لا تحل محل المحادثة.

## 5. التنقل والتكيف

### Compact أقل من 600dp

- البطاقة المفعلة ← `SCR-DS-001` إن لم يوجد اختيار صالح، وإلا تفتح آخر مساحة صالحة ثم محادثتها.
- `SCR-DS-002` شاشة كاملة: شريط علوي، سجل قابل للتمرير، ومؤلف رسالة مثبت فوق IME.
- زر «المحادثات» يفتح `SCR-DS-003` كـmodal drawer؛ زر «المصادر» يفتح `SCR-DS-006` كشاشة كاملة؛ شريحة النطاق تفتح `SCR-DS-009` كـbottom sheet قابلة للتوسع.
- Back يغلق أولاً sheet/drawer/dialog، ثم يعود من الأدوات إلى المحادثة، ثم من المحادثة إلى اختيار المساحة أو الرئيسة بحسب نقطة الدخول.
- تغيير المساحة مع مسودة غير مرسلة يطلب البقاء أو حذف المسودة وفق LATER-DRAFT-02؛ لا ينقل المسودة إلى مساحة أخرى.

### Expanded من 600dp فأكثر

- ثلاثة أجزاء عند توفر العرض: محادثات في start pane، المحادثة في الوسط، والمصادر في end pane.
- الوسط هو الجزء الأوسع دائماً. عند `fontScale >= 1.3` أو ضيق الارتفاع تختزل الواجهة إلى جزء رئيس مع drawers، حتى لا تضيق الرسائل أو المؤلف.
- `SCR-DS-009` يظهر داخل end pane أو sheet؛ لا تعيد القوائم ترتيب القراءة المنطقي: العنوان ← السجل ← المؤلف ← الأدوات المساندة.
- تغيير المساحة يمسح الأجزاء الثلاثة قبل الجلب؛ لا تظهر بيانات مساحتين معاً.

### الروابط والاستعادة

- لا deep link قبل تثبيت مفتاح الوكيل ومعرفات المساحة والمحادثة وعقد التفويض على `master`.
- عند استعادة العملية: يعاد فتح الحساب/المساحة/المحادثة نفسها، ثم يُجلب السجل وتُستعاد المسودة محلياً. لا تعاد رسالة قيد الإرسال تلقائياً.
- المحتوى المحلي للقراءة ليس تفويضاً. عند انتهاء الجلسة أو رفض الصلاحية يختفي السجل وأسماء الملفات فوراً وتظهر وجهة آمنة.

## 6. الرحلات

### J-DS-01 — الدخول واختيار المساحة

**المتطلبات:** DS-REQ-01..03، 14، 15

1. يتحقق التطبيق من عنصر Data Search وقدراته وصلاحياته من عقد مؤكد.
2. إن لم يتحقق، تبقى البطاقة «متاح لاحقاً» أو تعرض رفضاً آمناً بلا محتوى.
3. إن لم توجد مساحة مختارة صالحة، تعرض `SCR-DS-001` المساحات الموجودة فقط.
4. اختيار مساحة يثبتها كسياق ظاهر، ثم يجلب محادثاتها ومصادرها مع العزل بالحساب.
5. لا توجد مساحة: حالة مانعة مع تحديث ورجوع؛ لا زر إنشاء مساحة.

### J-DS-02 — فتح/بدء محادثة RAG

**المتطلبات:** DS-REQ-04، 06، 13..15

1. إذا كان للمساحة محادثات، يفتح أحدثها ويعرض عنوانها ونموذجها المؤكد ونطاقها.
2. إذا كانت فارغة، ينشئ العميل محادثة واحدة باسم «محادثة جديدة / New conversation» ثم ينتقل إليها؛ يمنع طلب الإنشاء المكرر أثناء الانتظار.
3. فشل الإنشاء يبقي المستخدم في حالة فارغة مع إعادة محاولة يدوية والرجوع للمساحات.
4. يجلب السجل بترتيبه. إن كان متعدد الصفحات، يحمّل الأقدم دون تكرار أو قلب ترتيب.
5. لا يقال إن السجل كامل ما دام cursor آخر موجوداً.

### J-DS-03 — سؤال وجواب مولد

**المتطلبات:** DS-REQ-06..09، 12، 14، 15

1. يكتب المستخدم رسالة؛ تحفظ مسودة معزولة حسب الحساب والمحادثة.
2. يظهر قرب المؤلف نطاق الاسترجاع: «كل المصادر المفهرسة» أو عدد الملفات المثبتة.
3. الإرسال متاح مرة واحدة فقط ما دام النص صالحاً والمحادثة جاهزة والاتصال/الصلاحية موجودين.
4. تظهر رسالة المستخدم تفاؤلياً بوسم إرسال، ثم «يفكر الوكيل»؛ عند وصول البث تتشكل رسالة المساعد تدريجياً.
5. نهاية البث المؤكدة تحول الرسالة إلى مكتملة، ثم يصالح العميل السجل مع الخادم ليحصل على المعرفات والحالة الفعلية.
6. إن انقطع البث، تبقى القطعة موسومة «رد غير مكتمل» ولا تتحول إلى نجاح. لا يعاد السؤال تلقائياً.
7. إن كانت نتيجة POST غامضة، يحتفظ التطبيق بالنص ويجلب السجل قبل تمكين إعادة المحاولة اليدوية.
8. Markdown والروابط والكود والنسخ متاحة وفق LATER-CHAT-03. مراجع المصدر تظهر فقط إذا أعادها العقد بصورة موثوقة.

### J-DS-04 — إدارة المحادثات

**المتطلبات:** DS-REQ-05، 13..15

1. يفتح المستخدم `SCR-DS-003` ويرى محادثات المساحة فقط.
2. إنشاء محادثة من `SCR-DS-004` يتطلب عنواناً صالحاً أو يسمح بالعنوان الافتراضي وفق العقد، ثم يفتح الجديدة.
3. إعادة التسمية تعدّل صفاً واحداً والعنوان المفتوح بعد تأكيد الخادم.
4. حذف `SCR-DS-005` يوضح أن سجل المحادثة فقط سيحذف وأن ملفات المساحة لن تتأثر.
5. إذا حُذفت النشطة، تفتح التالية؛ وإن لم تبق محادثة ينشأ/يعرض بدء محادثة حسب العقد المؤكد.

### J-DS-05 — إدارة مصادر المعرفة

**المتطلبات:** DS-REQ-10، 11، 14، 15

1. تفتح `SCR-DS-006` من المحادثة، وتعرض ملفات المساحة وحالة كل ملف وحالة مستنده/فهرسه منفصلتين.
2. يضيف المستخدم ملفاً عبر منتقي Android، أو نصاً يتحول محلياً إلى ملف إن أكد العقد ذلك.
3. `SCR-DS-007` يعرض التسجيل والرفع والإكمال والفحص والفهرسة كمراحل منفصلة؛ اكتمال الرفع لا يعني قابلية الاسترجاع.
4. الفهرسة تبدأ فقط بفعل وعقد وصلاحية مؤكدة. `pending/indexing/indexed/failed` لا تُختصر إلى نجاح عام.
5. `SCR-DS-008` يشرح أثر الحالة في الأجوبة ويتيح الأفعال المؤكدة فقط.
6. حذف المصدر عبر `SCR-DS-010` يوضح أنه لن يعود متاحاً لأي محادثة في المساحة، ويزيله من النطاقات المثبتة بعد تأكيد الخادم.

### J-DS-06 — تضييق نطاق الاسترجاع

**المتطلبات:** DS-REQ-08..10، 14، 15

1. تفتح شريحة النطاق `SCR-DS-009` من المحادثة.
2. الحالة الافتراضية «استخدام كل المصادر المفهرسة في هذه المساحة» ولا تُخزن كتثبيت ضمني.
3. اختيار ملف مفهرس يثبته للمحادثة. أول تثبيت يحول معنى النطاق إلى «المثبت فقط».
4. الملفات غير المفهرسة ظاهرة كتفسيرية لكنها معطلة ولا تدخل النطاق الفعال.
5. «استخدام الكل» يزيل كل التثبيتات ويعيد السلوك الافتراضي؛ لا يحذف ملفاً ولا يغير مساحة.
6. فشل تثبيت/إلغاء تثبيت يعيد عنصر التحكم إلى حالة الخادم ولا يغير جواباً سابقاً.

### J-DS-07 — تغيير النموذج

**المتطلبات:** DS-REQ-13، 14، 15

1. يظهر منتقي النموذج في المحادثة فقط إن وفر backend كتالوجاً مؤكداً والمسار متاحاً للمستخدم.
2. اختيار نموذج يثبت مفتاح توجيه لا اسم مزود حر.
3. الفشل يبقي المحادثة والنموذج السابق؛ لا يعيد إنشاء المحادثة.
4. «الافتراضي» يزيل التثبيت ويعرض الاسم الفعلي بعد رد الخادم.

## 7. الحالات المشتركة

| الحالة | السلوك |
|---|---|
| loading | skeleton/indicator مسمى لكل pane؛ لا يظهر فراغ كاذب أثناء الطلب. |
| no conversations | إنشاء أول محادثة مرة واحدة أو إعادة محاولة واضحة؛ لا وسط فارغ بلا تفسير. |
| no sources | المحادثة متاحة، لكن المؤلف يشرح أن الأجوبة من المعرفة تحتاج مصدراً مفهرساً؛ يفتح إضافة مصدر. |
| no indexed sources | لا يُقدّم جواب RAG موثق؛ يوضح أن المصادر تحتاج فهرسة. السلوك العام إن وُجد يحتاج عقداً صريحاً. |
| offline | السجل المحلي المقروء يوسم محلياً؛ إرسال/رفع/فهرسة/تثبيت معطلة، ولا إرسال تلقائي عند عودة الشبكة. |
| partial stream | الرد المرئي موسوم غير مكتمل مع مصالحة/إعادة محاولة يدوية، لا success. |
| permission denied | تحجب الرسائل وأسماء الملفات غير المصرح بها، وتظهر عودة آمنة. |
| session expired | تمسح الواجهة الحساسة وتوجه للدخول؛ لا تعتمد cache كتفويض. |
| process death | استعادة السياق والمسودة ثم جلب السجل؛ لا تكرار POST أو PUT. |
| account switch/logout | مسح الرسائل والمصادر والمسودات الخاصة بالحساب السابق قبل عرض الجديد. |

## 8. الوصول والتوطين

- كل أزرار الأيقونات لها أسماء موضعية، والأيقونات الزخرفية بلا وصف.
- ترتيب TalkBack في المحادثة: العنوان/السياق ← تنبيه الحالة ← الرسائل من الأقدم للأحدث ← حالة الرد ← المؤلف ← إرسال ← أدوات النطاق/المصادر.
- رسالة المساعد تعلن مرة عند اكتمالها؛ لا يعلن TalkBack كل token في البث.
- حالات «يرسل/يفكر/غير مكتمل/فشل» مكتوبة ولا تعتمد على اللون أو الحركة.
- نصوص Markdown والكود قابلة للتحديد والنسخ؛ الكود LTR داخل العربية.
- المؤلف وأزراره تبقى فوق IME، وكل هدف لمس 48dp، ولا تُقص الأزرار عند font scale 1.3–2.0.
- تستخدم الحشوات `start/end`، وتنعكس الأسهم الاتجاهية فقط؛ ترتيب الزمن والرسائل لا ينعكس.

## 9. قرارات مطلوبة قبل التنفيذ

1. مفتاح Data Search، قدراته، وصلاحياته على `master`.
2. عقود المساحات والمحادثات والرسائل، شكل SSE ونهاية البث، وترقيم سجل الرسائل.
3. هل يعيد جواب RAG استشهادات منظمة، وما حقول المصدر المسموح بعرضها؟
4. عقد تثبيت ملفات المحادثة ودلالة «لا تثبيت = كل المساحة».
5. عقد الملفات والفهرسة: MIME، الأحجام، `text/plain`، حالات السلامة، وسياسة الروابط المنتهية.
6. كتالوج النموذج ومسار تثبيته، وسياسة غياب مصادر مفهرسة.
7. سياسة cache والمسودات والتشفير/المسح المحلي.

هذه الموانع لا تمنع مراجعة التصميم، لكنها تمنع ادعاء الجاهزية أو تنفيذ التكامل المتأثر.
