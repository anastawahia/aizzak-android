# توحيد وثائق المشروع — DOCUMENTATION-CONSOLIDATION-01

التاريخ: 2026-11-06  
الحالة: مكتمل

## الطلب

جمع وثائق المنتج والتصميم والتنفيذ والتسليم التي كانت موزعة بين أربعة مواقع، ووضعها تحت `docs/` في هيكل واحد يسهل تتبعه وتسليمه بين الفرق.

## النتيجة

- نُقلت وثائق النطاق والمرجع الوظيفي إلى `docs/product/`.
- نُقلت مواصفات التصميم والمعاينة إلى `docs/design/`.
- نُقل التصميم التقني إلى `docs/architecture/`.
- نُقلت حزمة OpenAPI كاملة إلى `docs/api/`.
- نُقلت سجلات المهام والأدلة والاختبارات إلى `docs/delivery/`.
- نُقلت الخطة القديمة إلى `docs/archive/legacy-plan/` ووسمت كمرجع غير حاكم.
- أضيف فهرس عام وفهرس للتسليم، وحُدّثت تعليمات المشروع وإعدادات الأدوار المحلية كي تكتب السجلات الجديدة تحت `docs/delivery/`.
- لم تُعدّل ملفات الباك إند أو إعداداته أو فروعه.

## التحقق

- حُفظت الملفات الأصلية كلها: 491 ملفاً قبل النقل، ثم 495 ملفاً بعد إضافة فهارس التوثيق الثلاثة وسجل مهمة التوحيد.
- المسارات القديمة الثلاثة في جذر المشروع لم تعد موجودة.
- فُحص 210 رابطاً محلياً في Markdown بعد النقل؛ لم يبق رابط ملف مفقود بعد تصحيح مرجع ناقص داخل مواصفة الـAPI. تعبير Python داخل كتلة كود ليس رابط Markdown فعلياً.
- نجح `git diff --check` برمز خروج 0.
- لم يُشغّل بناء Android لأن التغيير تنظيمي وتوثيقي فقط ولا يمس مصدر التطبيق أو Gradle.

## ملاحظة توافق الأدوات

نسخة `suite.py` المضمّنة في الإضافة الحالية تثبّت بعض مخازنها على مسار قديم. تمنع تعليمات المشروع إعادة إنشاء شجرة توثيق موازية؛ تُستخدم مسارات تقارير صريحة تحت `docs/delivery/evidence/` حيثما تدعمها الأداة، ويُسجل عدم التوافق عندما لا تسمح بتغيير جذر السجلات.
